# 样本验收与评测

## 1. 用途与现状

本文件定义三件事：当前样本应该显示什么、交互任务怎样算通过、哪些误导必须避免；并列出待补样本和验证记录格式。字段语义以 [04](./04-sample-and-metric-catalog.md) 为准，界面行为以 [02](./02-product-and-interaction.md) 为准，性能预算以 [03](./03-implementation-and-validation.md) 为准。

P0 条目（§2–§5 与 T1–T10）已于 2026-10-10 在 Obsidian 内验收通过，记录见 §7。此后新增的条目仍按静态预期管理，未运行前不得标记"通过"。行号引用以 2026-09-19 快照为准，仅供人工核对；实现按内容版本重建位置。

## 2. test-1.md 静态预期

### 概览应显示

- 标题 Omarchy，顶部有固定笔记与来源详情入口。
- 摘要取 `tldr`，标注"来自 tldr"；预览折叠但不改写原文。
- 三行主指标：影响力 2.5（置信度：高）、复利价值 4.0（置信度：中）、炒作程度 中（置信度：高），并显示"数值量程未配置"。
- 维度入口：风险 4 类 + 1 补充、机会 3 条、对象 1 个主体、影响（受益 4 项 / 承压 3 项）、内容结构、其他判断。

### 详情应显示

- 复利价值详情：4.0、"量程未配置"、置信度中、reason 预览（最多 6 行、标明"原文预览"）、依据区含"定位字段"和"外部来源"两个独立入口。
- 风险视图：四个等面积分类格（监管/技术/竞争/伦理，各写类别名）+ 补充入口；标题为"风险分类"，无红黄绿、无概率×影响坐标。
- 对象详情：Omarchy 定位、product/market 两个信号、3 项目标用户、3 条对象风险、对象评分 5.0（旁注"定义及量程未声明"）；technical/adoption/ecosystem 三项显示"未提供"，不画空卡。
- 来源详情：`published` 2026-09-03 与正文 Feed 日期 2026-09-04 并列保留；`author` 的 Zac Zuo 与正文提交者 DHH 并列，不合并、不纠错。

### 不得出现

- 指标展示、筛选、排序、推荐中出现 `extraction_status`、`pipeline_stage`、`extract_result`、`epistemic_status`、`engineering_complexity`、`actionable_insight`。
- 百分比、进度条、雷达图、综合分、跨指标排名；风险红黄绿或严重度推断。
- 把 mention 的 `confidence: high` 附到对象评分 5.0 上；把 mention 与 insight 中相同的中文片段当作两份独立证据；把"0 赞 2 评论"当作 reason 全部市场推断的正文核实。

## 4. 交互任务与通过条件

操作次数从"面板显示目标笔记概览"起算。记录指标对应 [01](./01-product-assessment.md) §6：找到理由的时间、定位成功率、量程/来源误解、操作次数。

| 编号 | 任务 | 操作路径 | 通过条件 |
| --- | --- | --- | --- |
| T1 | 找到复利评分理由并定位字段 | 概览点"复利价值"→ 详情读 reason → 点"定位字段" | ≤2 次操作发起定位；高亮落在当前版本 `compound_value.reason` 范围内；分值、理由、置信度同组显示 |
| T2 | 确认缺失信号不是零值 | 概览 → 对象 → 查看信号区 | 三项显示"未提供"；无空图表、无 0 值；追问时试用者回答"没有这项数据"而非"得零分" |
| T3 | 找技术风险并固定关注 | 风险入口 → 技术格 → 读原文 → 固定关注 | 四类等面积且类别名完整；详情一次只展开技术一项；固定后顶部出现紧凑关注条 |
| T4 | 固定关注跨笔记返回 | T3 后切到另一篇（如 test-2），再点关注条 | 面板正常跟随显示新笔记；关注条显示原笔记名；点击后回到 test-1 的技术风险详情 |
| T5 | 区分三种来源 | 复利详情打开依据区 | "定位字段"与"外部来源"为独立操作；无正文定位入口（中文摘录不声称正文命中）；标注"来自笔记字段，生成方式未知" |
| T6 | 置信度各归其主 | 查看炒作详情与对象详情 | `confidence.hype` 只随炒作程度；mention 的 high 标为"提及识别置信度"；对象评分旁无整篇置信度 |
| T7 | 快速切换不串内容 | test-1 ↔ test-2 快速交替 10 次 | 无旧理由配新分、无残留指标；过期异步结果被丢弃 |
| T8 | 定位过期处理 | 固定关注后编辑 YAML，移动或删除 `compound_value.reason` | 移动后重新解析并唯一恢复才定位；删除时提示"内容已变化"，不跳旧行号、不以邻近条目顶替 |
| T9 | 排除泄漏检查 | 浏览全部维度、详情与关联区 | 六个排除字段不以指标、排序项或推荐出现；原始 YAML 仍可经原文入口查看 |
| T10 | 量程误解检查 | 试用者看概览后回答"2.5 是满分多少的 2.5？" | 界面已显示"量程未配置"；记录误解率作改进基线，不因误解而擅自补画刻度 |

T10 是误导测量而非知识测验：不要求试用者答对，目标是让误解率可被记录和下降。T2 同理。

## 5. 异常用例预期

P0 验收前逐条构造，预期显示与 [02](./02-product-and-interaction.md) §8 一致：

| 用例 | 通过条件 |
| --- | --- |
| 空文档（库中新建空白笔记） | 文件名 + "还没有内容"，无上篇指标 |
| 无 YAML 的普通笔记 | 正文摘要/标题概览与可用链接，无报错 |
| 部分 null / 空数组 | 不画空卡；详情可展开"未提供"项（如空 companies 组） |
| 字段类型异常（如 score 为字符串） | 该项显示原值或无法解析，其余维度不受影响 |
| YAML 编辑中 / 解析错误 | 提示更新或无法解析；旧结果整组标"上次有效内容"并停用旧定位，不混用新旧值 |
| 无关联笔记 | 明确"未找到已有关系"，不以候选填充 |
| AI 失败 / 缓存过期（S3 后） | 基础阅读可用；缓存标过期，手动更新，不自动重试 |

## 8. 初版已知限制（P0 已验收，以下为遗留限制）

初版实现（0.1.0）经两轮代码审查后仍保留的限制，P0 验收时已逐条确认可接受，留待后续阶段处理：

1. **同路径编辑竞态**：快照守卫比对路径与版本一致性，但同一路径两次 refresh 乱序返回时旧版本仍可能短暂覆盖新版本（下次编辑自愈）。请求序号机制留待后续。
2. **返回后的焦点与滚动恢复**：进入详情时焦点移到"返回概览"按钮、Esc 可返回，但返回概览后不恢复原先的滚动位置与焦点元素。
3. **对象数组重排定位**：对象定位使用身份标量（url/name）指纹，重排后拒绝定位（安全降级），不做跨条目恢复。
4. **合并键（`<<:`）**：不展示、不定位，属声明过的 YAML 子集限制。

阶段完成定义与 [03](./03-implementation-and-validation.md) §8 一致：P0 用例已于 2026-10-10 全部通过，且错定位、状态泄漏、伪造量程/证据、跨笔记串内容四类阻断问题无一存在，项目可进入下一阶段。
