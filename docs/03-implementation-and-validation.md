# 实施路线与验证

## 1. 阶段与退出条件

先实现确定性的字段阅读闭环，再扩展可视化和智能能力。字段覆盖与视觉组件丰富度分开：P0 已能访问所有纳入范围的字段，P1 再改进特定维度的视觉组织。

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| S0：输入与定位验证 | 字段字典、状态排除、类型校验；嵌套 YAML 范围定位实验；两个当前样本的预期结果 | 折行 reason、数组条目可准确定位；缺失量程/证据无伪造；选定最低 Obsidian 版本 |
| S1 / P0：阅读闭环 | 面板、摘要、三项概览、风险/机会分类入口、其他维度通用详情、字段来源、固定笔记/关注、只读原文定位 | [05](./05-sample-acceptance.md) 当前样本及 P0 异常用例通过；单项详情、空文档、快速切换不串内容 |
| S2 / P1：视觉与关系 | 影响分组、完整对象视图、逻辑步骤、出链/反链、关联预览、受限一跳图、显示偏好 | 补齐真实关联样本；图与列表相同语义；桌面主题/键盘/宽度与性能通过 |
| S3 / P2：可选 AI | 手动摘要或理由压缩、后续语义关联；同口径比较另立方案 | S1/S2 已有阅读收益；服务、凭证、范围、缓存、质量验收明确 |

首个运行版本面向桌面；移动端另验。不依赖其他社区插件或外部数据库。技术栈选型（esbuild + React 19 + zustand + Tailwind 4）见 [06](./06-tech-selection.md)；图形只承担有限分类/选择，不预先引入大图布局引擎。

## 2. 数据归属与模块职责

| 数据/能力 | 归属 | 约束 |
| --- | --- | --- |
| Markdown 正文、YAML | Vault 原文件；编辑时当前编辑缓冲区 | 唯一可写业务来源；基础浏览不写回 |
| 元数据/链接 | Obsidian 缓存、公开解析接口 | 复用链接解析，不在切换时扫描全库正文 |
| 原文快照与字段位置 | 插件派生、按版本缓存 | 可重建，不复制为第二份业务文档 |
| 字段映射、量程、枚举、排除规则 | 插件设置 | 可版本化；原笔记无须迁移 |
| 当前目标、选择、固定关注 | 会话视图状态 | 不写入 YAML；持久显示偏好与临时关注分开 |
| 标签/实体/文章 ID 索引 | 插件派生缓存 | 增量维护，可清除重建；重复 ID 不选第一个 |
| AI 输出 | 可删除缓存 | 关联快照/模型/提示词版本，不覆盖原字段 |

职责分为：目标跟踪 → 快照读取 → 带位置的解析 → 指标适配 → 关系查询 → 视图投影 → 定位。数值、置信度、理由和来源由适配层统一绑定；界面不能各自猜字段语义。

## 3. 最小数据契约（设计草案）

```ts
type PathPart = string | number;

interface SourceRef {
  noteKey: string;              // 会话内文件身份，重命名时不换成另一篇
  contentVersion: string;       // 精确文本指纹，不只用 mtime
  kind: "frontmatter" | "body" | "external";
  path?: PathPart[];            // 如 ["object_insights", 0, "score"]
  range?: { from: number; to: number }; // 当前快照 UTF-16 偏移，半开区间
  url?: string;
  match: "field" | "exact-body" | "unverified";
}

interface MetricSpec {
  key: string;
  valuePath: PathPart[];
  reasonPath?: PathPart[];
  confidencePath?: PathPart[];
  subject: "article" | "object";
  kind: "number" | "category" | "text" | "list";
  scale?: {
    min: number; max: number;
    meaning: string;
    direction: "higher" | "lower" | "none";
    version: string;
  };
}

interface FacetItem {
  key: string;                 // 文档 + 维度 + 条目身份；不把数组下标当永久身份
  metricKey?: string;
  subjectKey: string;
  value: unknown;               // 通过适配器校验后交给相应视图
  availability: "present" | "missing" | "null" | "empty" | "invalid";
  reason?: string;
  confidence?: string;
  refs: SourceRef[];            // 每个值/理由/片段都保留自己的来源
}
```

以上内部 availability 是运行数据情况，不是用户排除的笔记状态指标。排除路径在生成 FacetItem 前过滤。unknown 值经类型守卫处理，不直接拼成 HTML；文本按文本渲染，外链只允许受支持的安全协议，笔记内容不得执行脚本。

数组条目选择用对象身份或文本指纹与父路径重定位：对象可用类型+确切 URL；无身份的文本项在新版本唯一匹配时恢复，重复或改写时要求重选。当前快照的数字索引只负责定位，不作为跨版本身份。

量程配置必须满足有限数值、min < max，并具备含义和版本；越界保留原值、停止绘制比例。confidence 的值不经过数值转换；原因、置信度缺失分别显示缺口，不能从其他维度借值。

## 4. 解析与原文定位

Obsidian 的 frontmatter 缓存提供字段值和整体区域信息，不能据此假设拥有每个嵌套标量的范围。编辑器公开滚动/选区接口和内部链接解析可用于导航；元数据 changed 不覆盖重命名，应监听 Vault rename。依据：[官方 API 定义](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)，查阅日期 2026-09-19。

因此 S0 必须验证下面的自有定位层：

1. 从当前快照识别文件起始 frontmatter，不用正则拆整个 YAML 结构。
2. 选择能保留语法节点位置的 YAML 解析方式，同时输出类型值与路径→范围映射；具体库在实现时选型并验证。
3. 为 folded/multiline 字符串保存原始源范围，而非把解码后文本拿去全文搜索。定义换行、BOM 与 UTF-16 偏移转换规则。
4. 数组按当前路径定位；重复键、别名/合并键等出现位置歧义时不给“精确值定位”，退到字段区域并说明，禁止错跳。
5. 字段内摘录只能定位该字段。正文依据仅接受当前快照唯一精确匹配；跨语言、模糊相似、多处重复一律不自动宣称正文命中。
6. 点击前核对版本：变化时重新解析，能唯一恢复目标才定位；目标删除或无法匹配则提示重选。
7. 阅读模式不能显示 YAML 时，“定位字段”明确打开可显示源码的编辑视图；不改文件。保留原视图/位置以便返回，实际模式切换可行性在 S0 验证。

解析故障局部降级：整个 YAML 无效时该版本不产出新指标，正文仍可阅读；显示旧结果时必须整组标“上次有效内容”，并停用旧位置。不能混合新 score、旧 reason、旧置信度。

## 5. 更新流程与一致性

```mermaid
flowchart LR
    A[有效 Markdown 目标] --> B[带身份和版本的快照]
    B --> C[解析字段与源范围]
    C --> D[排除状态并绑定指标]
    D --> E[单次发布视图快照]
    B --> F[查询关系缓存]
    F --> G[检查目标和索引版本]
    G --> E
    E --> H[概览或选中详情]
    H --> I[点击定位前再核对版本]
```

文本等价：确定目标 → 读取同一版本内容 → 解析与过滤 → 绑定值/理由/置信度 → 发布完整字段快照；关系另查缓存并校验版本 → 用户选择详情 → 定位前再核对。

- 面板不抢焦点。点击侧栏时仍保留最近有效 Markdown 目标；分屏按最后激活的 Markdown 编辑器处理，不从侧栏活动视图猜文件。
- 会话目标使用文件身份并维护最新路径，异步任务携带目标、内容版本、配置版本与请求序号；任一不符则丢弃。
- 活跃编辑文档优先取编辑缓冲区；相关缓存若对应旧文本，关系区单独显示等待更新，不混入新快照。其他打开的同文件编辑器以当前目标 leaf 为准。
- 编辑防抖建议起点 200ms，随后测量调整；固定笔记仍刷新内容，固定关注在同版本内保留，不自动跳另一项。
- 监听文件创建、修改、重命名、删除及元数据/链接解析事件。更新反链、标签和 ID 索引；重命名迁移引用，删除使目标和关注入口失效。
- 关系缓存未就绪时使用明确占位，不能沿用上一篇列表。全库初次索引异步分批进行，排除目录不参与候选。
- 面板隐藏时暂停昂贵图形渲染，保留必要失效标记；再次打开读取最新快照。卸载时注销监听、定时器和图形资源。

## 6. 关系与性能预算

优先复用 Obsidian 已解析链接，保留来源路径与子路径（标题、块引用）；author 中的链接也交给统一解析。对象名不是链接。文章 ID 索引返回集合：缺失显示未找到，重复显示有歧义，当前文章排除自环。

推荐数量、排序、图例及上限统一按 [02](./02-product-and-interaction.md)，图和列表共享同一关系模型，图不能自行增加边。P0 不要求跨库索引，P1 才启用完整关系能力。

| 目标 | 测量方法 | 边界 |
| --- | --- | --- |
| 已索引切换 P95 ≤300ms | 从有效目标事件到主指标可见，至少 100 次 | 不包含 AI；记录设备、版本、库规模、缓存情况 |
| 已加载详情响应 P95 ≤100ms | 点击到详情绘制，至少 50 次 | 超长文本展开另记，不阻塞全页 |
| 连续输入不显著变慢 | 与关闭插件基线对照输入延迟、长任务 | >50ms 主线程任务需定位原因，目标并非已达成 |
| 图形容量固定 | 一跳最多 12 个邻居；列表每页 20 条 | 展开再渲染，总数与省略提示可见 |
| 冷启动可解释 | 单独记录首次可读、索引完成时间和峰值内存 | 不用热缓存结果替代冷启动 |

先测当前样本，再测约 30 篇真实样本和 1,000 篇标记为合成的性能库。超过预算优先减少重复解析、按需渲染、增量索引；是否需要 Worker 应由性能剖析决定。

## 7. AI 与隐私的后续边界

网络调用默认关闭。模型服务、凭证存储、调用协议、长文限制在 S3 明确；手动触发前说明发送范围，默认只当前笔记或选中章节，不递归上传关联文档。不能静默截断超长内容。

结果缓存绑定原文指纹、模型、提示词版本、生成时间。原文变化标过期，不自动重试或重新消费额度。失败保留基础阅读能力。正文里的指令是待处理内容，模型无文件写入或工具执行权限；结果不自动写回 Markdown。已有字段中看似 AI 生成的措辞不作为实际生成者判定依据。

## 8. 验证门槛与交付证据

单元验证针对映射、排除、类型边界、来源范围、重复对象、去重及版本保护；宿主验证负责分屏、主题、焦点、模式切换、文件生命周期及性能。完整用例见 [05](./05-sample-acceptance.md)。

每阶段交付：实现版本、通过/失败用例、环境、原文哈希前后对比、已知限制、性能记录。P0 错定位、状态泄漏、伪造量程/证据、跨笔记串内容任一未解决，不进入下一阶段。当前仅文档与样本静态核对，不能填报插件测试通过。
