# 创意评估与产品定位

## 1. 结论与本轮调整

**产品重点从“汇总属性”推进到“把多维判断变成可探索、有依据的阅读入口”。** 首版围绕“概览 → 选维度 → 看依据 → 定位”形成闭环，排除状态指标。

| 原方案 | 样本揭示的问题 | 本轮决策 |
| --- | --- | --- |
| 摘要、属性、关联卡片 | 37 个顶层字段，大量嵌套对象和长理由 | 建立指标字典，分层组织，不逐字段堆卡片 |
| 数字用进度条 | 2.5、4.0、5.0 均无量程 | 先显示原值；有明确口径后才显示刻度 |
| 局部关系图辅助阅读 | 核心信息在单篇风险、对象与判断中 | 先做好维度概览，文档图谱仍为辅助 |
| 摘要返回正文 | 分析多在 YAML，中文摘录不是英文正文原句 | 区分字段定位、正文原句与外部来源 |
| 展示关键属性 | 状态占空间，不同评分也容易混比 | 状态排除；不同主体、维度、口径分别呈现 |

完整字段去向见 [04](./04-sample-and-metric-catalog.md)。

## 2. 用户场景与产品价值

| 用户的问题 | 先看到什么 | 如何锁定关键内容 | 有用的判据 |
| --- | --- | --- | --- |
| 是否值得继续读？ | 摘要、影响力/复利价值/炒作程度 | 选指标查看理由和来源 | 能解释关注原因，而非只记数字 |
| 为什么这样打分？ | 原值与对应置信度文字 | 指标 → reason → 字段原文 | 不混淆分值、置信度与事实可靠性 |
| 风险在哪里？ | 四类风险入口和补充项数量 | 技术风险 → 单项详情 → 固定关注 | 不必扫读整个 risk_matrix |
| 谁受益、谁承压？ | 两组等权对象和机会入口 | 选条目看原有分析 | 不把并列分组误认为逐对因果 |
| Omarchy 值得关注什么？ | 对象定位、已有信号 | 产品/市场信号 → 风险 → 依据 | 缺失信号不被理解为零分 |
| 接下来读哪篇？ | 实际引用与独立候选关系 | 看原因 → 预览 → 打开 | 能区分推荐和引用 |

继续服务知识学习与摘录回顾。样本新增“结构化分析摘录”预设，不把插件转成投资分析或流水线管理工具。普通笔记仍使用摘要、标题概览与关联视图。

## 3. 样本支持哪些判断

| 观察 | 产品含义 | 不能据此声称 |
| --- | --- | --- |
| YAML 位于第 1～142 行，正文很短 | 字段定位和长理由阅读是核心 | 正文足以验证所有分析 |
| 两个文章评分都有 score/reason | 数字、理由、置信度成组 | 评分同量程、能够相加 |
| confidence 对应 impact/compound/hype | 分别绑定维度 | high 等于 90% 或整篇可信 |
| risk_matrix 为文字 | 等面积分类格，数量仅代表条目 | 已有概率、严重度、风险总分 |
| 两组对象都提及 Omarchy | 可合并入口但保留来源 | 重复摘录等于多份独立证据 |
| 三个对象信号为 null | 明确“未提供” | 技术不存在或采用率为零 |
| test-2 为第二篇同 schema 样本 | 适配层回归与取值形态对照 | 已有跨笔记关系样本（两篇仍无相互链接） |

engineering_complexity 的值为 production_ready，information_entropy 定义未知，author 与正文提交者不同。这些都要求保留语义边界，不自动修正、量化或合并身份。

## 4. 可行性与差异化

| 能力 | 评估 | 核心验证 |
| --- | --- | --- |
| 嵌套字段组织 | 可实施，需自有字段模型 | 类型异常、空值、未知枚举 |
| 可视概览与按项钻取 | 复杂度可控 | 在窄侧栏完成任务，不堆叠图表 |
| YAML 精确定位 | 首版技术重点 | 折行、数组重排、未保存编辑 |
| 事实关系与候选关联 | 可利用公开接口 | 同名、缺目标、跨笔记索引 |
| 可选 AI | 后续扩展 | 生成内容标记、依据校验、隐私与成本 |

Obsidian 公开 API 的视图、编辑器与元数据能力可作为实现基础，运行行为仍需验证。依据：[官方 API 定义](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)。具体验证安排见 [03](./03-implementation-and-validation.md)。

差异化假设是把“内容 → 多维判断 → 对应依据 → 原文”连接成短路径，而不是重复属性列表。本轮不作新的竞品能力结论；旧方案提及的 Properties、Backlinks、Bases 与智能关联工具留到发布前做实际任务对照。

## 5. 优先级与非目标

| 优先级 | 范围 | 下一步条件 |
| --- | --- | --- |
| P0 | 映射、状态排除、概览、聚焦详情、原文定位、关注锁定、空笔记 | 样本预期结果与定位准确性通过 |
| P1 | 影响分组、完整对象详情、显式关系列表/受限图、显示偏好 | P0 不误导，关联样本补齐 |
| P2 | 可选 AI 摘要、语义关联、同口径跨笔记比较 | 有阅读收益，口径与质量规则齐备 |

不做自动综合分、置信度加权排名、状态看板、文字推断风险等级、全库大图、自动改写 YAML 或创建链接。状态排除适用于指标展示、筛选、排序和推荐；界面的加载、失败等运行反馈仍必须保留。

## 6. 成功标准与命名

优先衡量找到理由的时间、定位成功率、量程/来源误解、操作次数，再看是否愿意长期保留面板。具体任务与通过条件见 [05](./05-sample-acceptance.md)。两篇无互链的同 schema 样本不能证明泛化或产品成功。
